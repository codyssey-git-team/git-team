## 커밋 메시지 컨벤션

팀 내 일관된 변경 이력 관리와 원활한 협업을 위해 [Conventional Commits](https://www.conventionalcommits.org/) 표준을 따릅니다.

### 1. 커밋 메시지 기본 구조

```text
<type>(<scope>): <subject>

<body>

<footer>
```

- **Header (`<type>: <subject>`)**: 필수 항목입니다.
- **Body**: 선택 항목이며, 변경 이유와 상세 내용을 기술할 때 작성합니다.
- **Footer**: 선택 항목이며, 이슈 번호 참조나 Breaking Change 등을 표기할 때 사용합니다.

---

### 2. 타입(Type) 목록

| 타입 | 설명 |
| :--- | :--- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 (README, 가이드 등) |
| `style` | 코드 의미에 영향을 주지 않는 변경 (포맷팅, 공백, 세미콜론 등) |
| `refactor` | 코드 리팩토링 (기능 추가 또는 버그 수정이 없는 코드 변경) |
| `perf` | 성능 개선을 위한 코드 변경 |
| `test` | 테스트 코드 추가 또는 기존 테스트 수정 |
| `chore` | 빌드 업무 수정, 패키지 매니저 설정, 환경설정 변경 등 |

---

### 3. 세부 작성 규칙

- **제목 (Subject)**
  - 50자 이내로 간결하고 명확하게 작성합니다.
  - 마침표(`.`)는 끝에 붙이지 않습니다.
  - 무엇을 변경했는지 드러나도록 개조식 또는 명령조로 작성합니다.
  - (선택) 작업 영역이 명확한 경우 `scope`를 추가할 수 있습니다. (예: `feat(auth): 로그인 유효성 검사 추가`)
- **본문 (Body)**
  - 제목만으로 설명이 부족한 경우, 무엇을(What) 왜(Why) 변경했는지 작성합니다.
  - "어떻게(How)"보다는 "무엇을", "왜"에 집중하여 서술합니다.
- **꼬리말 (Footer)**
  - 관련 이슈 번호를 명시할 때 사용합니다.
  - 예: `Closes: #123`, `Fixes: #45`, `Ref: #67`

---

### 4. 의미 없는 커밋 메시지 금지 (판정 기준)

아래 항목 중 하나라도 해당하면 **"의미 없는 메시지"**로 간주합니다.

- **변경 대상을 유추할 수 없는 단어만 있는 경우**: `update`, `fix`, `temp`, `wip`, `final` 등
- **무엇을/왜 바꿨는지 드러나지 않는 경우**: `bug fix`, `edit file` 등 (구체적인 대상 또는 변경 효과 없음)

---

### 5. 커밋 메시지 예시

#### 기본 예시
```text
feat: 사용자 로그인 API 연동
```

#### 본문 및 이슈 번호 포함 예시
```text
fix(checkout): 결제 수단 미선택 시 주문 처리 오류 수정

결제 수단을 선택하지 않은 상태에서 결제 요청 시
NullPointerException이 발생하는 문제를 방지하기 위해 유효성 검증 로직을 추가함.

Closes #42
```



## PR 규칙 / 코드 리뷰 규칙

### PR 본문 필수 항목
- `Closes #이슈번호` — 어떤 이슈를 처리하는 PR인지
- What — 무엇을 바꿨는지
- Why — 왜 바꿨는지
- How — 어떻게 테스트/검증했는지

### 병합 조건
- 리뷰어 1명 이상 Approve

### 코드 리뷰 규칙
- "LGTM"만 남기는 리뷰 금지. 코드 줄을 지정한 실질 코멘트 1개 이상
- 리뷰는 Conversation 일반 코멘트가 아니라 Files changed 라인 코멘트 → Review changes(Approve / Request changes)로 제출
- 작성자는 코멘트를 반영한 커밋을 push한 뒤 그 스레드에 "반영했습니다: <커밋 해시>" 답글
- 좋은 코멘트 예시
  - "이 함수에 음수가 들어오면 어떻게 되나요?"
  - "docstring에 반환 타입도 적어주면 좋겠습니다."
  - "빈 리스트일 때 IndexError가 날 것 같습니다."
- 예시: [PR #6](https://github.com/codyssey-git-team/git-team/pull/6)의 리뷰 스레드
